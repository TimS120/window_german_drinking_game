# Window move-proposal agent specification

This is the complete product and engineering specification for the first Window
ML agent.

## Product objective

Train an advisory agent that proposes the best legal next move for the current
player. “Best” means minimizing that player's expected total drinks from the
current decision until the game is complete.

This is a competitive objective: every player minimizes their own drinks, not a
shared table total. The first implementation is single-player for simplicity reasons.

The agent is advisory only. It may highlight a move but must never execute it,
bypass a confirmation, alter a turn, or replace the Flutter rules engine.

## Work-Packages scope

The first agent is a feed-forward, current-state policy. It receives neither
action history nor previous board states. This is deliberate: the deployed
Flutter/ONNX contract is stateless, and current public information is enough
for a valid first policy.

History, recurrence, or earlier board states are future work. They require an
explicit versioned change to the Flutter state model, ONNX interface, trainer,
exporter, and compatibility tests. Do not add them implicitly.

## Information boundary

The agent may receive only information directly visible to a player when the
proposal is made:

- the Window layout and which positions are occupied
- which cards are face-up and their visible ranks
- which positions are face-down
- whether the handle rule restricts selection
- whether the player may pass
- the legal action mask derived from those public facts

The agent must not receive, query, or turn into an explicit feature:

- identities, ranks, suits, order, or count of deck/face-down cards
- random-generator state or future redeal outcomes
- the answer to the current guess
- hidden-card lookup data, or handcrafted probability/statistical features
- host-only Firebase state
- future states and actions

The network may learn patterns from compliant observations during training.
That is different from giving it privileged engineered statistics.

## Out of scope

- Automatic gameplay or autonomous drinking decisions
- Hidden-information/deck-aware oracle features
- Multiplayer strategy (competitive --> cooperative), collusion, opponent modelling
